## 2. Deliver the saved-file loading boundary only

Proposed interface `load_snapshot(selection, manifest, saved_root, limits) -> Ok[HistoricalSnapshot] | Blocked | Rejected`. Make minimal immutable DTOs for a block-bound read-only view, per-field origin/source refs, component status, requested/available coverage, source-selection and quarantine ledger. No state transition, valuation/HF recomputation, swap quote or callable execution method. Metadata/time returned by the loader must not alter source bytes or immutable historical observations.

Required loading order: validate trusted manifest/selection/schema → resolve safe allowlisted files → check compressed/raw sizes and hashes → bounded decode → verify declared decoded bytes → strict source-schema parse → field-aware typed mapping → identity/time/unit checks → completeness/capability classification → immutable deterministic content projection. Never invoke collector.py/verify_saved.py reconstruction functions or clients while loading. No network, credential/environment-source discovery or default RPC fallback on import/test/constructor/error.

Preregister loader limits before parsing: max input file 8 MiB compressed/raw, decoded file 64 MiB, decoded pack 256 MiB, JSON depth 128, manifest entries 512, pool tick records 10,000 per pool-block, portfolios 64 per block, reserves 128 per portfolio, discovery headers 2048 per component. These are resource bounds for this saved pack, not claims of market coverage. Check actual manifest maxima first; if a bound is insufficient, BLOCKED with measured size and proposed explicit revision, never truncate, raise limits silently or label incomplete data complete. Stream decompression and count actual bytes; reject gzip bombs/trailing unsupported members or malformed data with explicit scope. A supported concatenated-gzip policy must be documented/tested if used. Strict JSON duplicate-key/nonfinite rejection; no pickle, eval, dynamic imports, arbitrary object deserialization or unbounded path traversal/symlink escape.

Raw saved JSON intentionally mixes integers, booleans, decimal strings and opaque ABI vectors; map known fields by schema. Use explicit from_int for native JSON integers and exact canonical-string constructors for string quantities. Do not globally coerce bool/int, string True/False, null/0, symbol/address or every numeric-looking string. Preserve unsupported opaque ABI entries with origin/locator; they do not establish native executable state. Unknown/malformed required fields reject/quarantine; genuinely unavailable fields are tagged MISSING/UNSUPPORTED with refs, never observed zero.
